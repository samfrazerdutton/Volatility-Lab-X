# Baseline

Measured state of the repository at commit `4da82eb` (2026-10-07), before any
work on the Volatility State Compiler directive (deterministic event runtime,
replay, SIMD, thread pool, million-state benchmark, regime/factor/cross-
underlier engines, CLI, Python bindings, research console).

Every number below was produced by actually running the command shown, on
this machine, just now. Nothing here is estimated or carried over from a
different machine or a different day. Where a number cannot yet be measured
(no benchmark harness exists yet, profiling has not been set up yet), that is
stated explicitly rather than filled in with a guess.

## Build tool note (environment quirk worth recording)

`ninja` is not on this shell's `PATH` by default. The working `ninja.exe` on
this machine is a pip-installed copy at
`/c/Users/samca/AppData/Roaming/Python/Python312/Scripts/ninja.exe` (from
some earlier `pip install ninja`), not a system-wide install. Every build in
this document was run with that directory prepended to `PATH`. A fresh clone
on a different machine needs *some* generator available to CMake (`Ninja`,
`NMake Makefiles`, or a Visual Studio generator) — this is noted here so a
future "the build doesn't configure" report starts from the right place
instead of re-discovering this.

## Configure flags used for this baseline

```
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo \
      -DCMAKE_CXX_COMPILER=clang++ \
      -DVL_BUILD_BENCHMARKS=OFF -DVL_BUILD_EXAMPLES=OFF -DVL_BUILD_CLI=OFF
```

The last three are off only because `benchmarks/`, `examples/`, and
`apps/cli/` are empty placeholder directories with no `CMakeLists.txt` in
them yet (see Gaps). `CMakeLists.txt` defaults all three to `ON`; turning
them on with nothing inside is a hard CMake configure error
(`add_subdirectory` on a directory with no `CMakeLists.txt`), confirmed by
reproducing it directly. `tests/` (`VL_BUILD_TESTS`) is populated and stays
on.

## Code size

```
include/: 6,660 lines across *.hpp
src/:      6,642 lines across *.cpp
tests/:    7,872 lines across *.cpp
```

Tests outweigh implementation, which matches this project's own stated
practice: every nontrivial formula gets probed against an independent
reference before a formal test is written, and the formal suite is written
to be at least as thorough as the probe.

`grep -rn "TODO\|FIXME\|XXX"` across `include/`, `src/`, `tests/`: **zero
matches.** There is no backlog of known-broken code hiding behind a marker
comment; anything incomplete is an empty, unpopulated module (see Gaps), not
a half-finished one.

recorded here as the first data point.

## What has not been measured yet, and why

- **No SIMD throughput/error numbers.** `kernels/simd/` has no source files
  (see Gaps) — there is no SIMD kernel to benchmark yet. The directive's
  Phase 3/9 numerical-contract work starts from zero, not from an existing
  implementation needing re-validation.
- **No thread pool / parallel reduction numbers.** `kernels/parallel/` is
  equally empty, and there is no `std::thread`/thread-pool code anywhere in
  `src/` or `include/` (`grep -rln "std::thread\|ThreadPool"` returns
  nothing).
- **No million-state benchmark, no performance regression harness.**
  `benchmarks/` is an empty directory; `VL_BUILD_BENCHMARKS` cannot even be
  turned on against it yet.
- **No memory/allocation/cache profiling.** No profiler is wired into the
  build. This is deferred to the directive's profiling phase rather than
  improvised with an ad hoc tool here.
- **No deterministic event stream, replay engine, or state hashing exist
  yet.** This baseline predates all of that; it is the "before" picture the
  directive's Phase 1-5 work is measured against.
